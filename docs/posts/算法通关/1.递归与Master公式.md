## 一、先看一个最简单的递归：求数组最大值
我们用一个经典案例来理解递归——**用递归的方式求一个数组中的最大值**。

思路很直观：

1. 如果当前区间只有一个元素（左边界 `l` 等于右边界 `r`），那它自己就是最大值，直接返回——这就是 **base case（基线条件/终止条件）**。
2. 否则，把当前区间从中间劈成左右两半。
3. 递归求出左半区间的最大值、右半区间的最大值。
4. 两个最大值再比一次，返回更大的那个。

### C++ 版本
```cpp
#include <iostream>
#include <vector>
#include <algorithm>   // std::max 头文件
using namespace std;

/**
 * @brief 递归函数，求数组 arr 在 [l, r] 闭区间内的最大值
 * @param arr 源数组，const引用避免拷贝，提升性能
 * @param l 当前处理区间左边界
 * @param r 当前处理区间右边界
 * @return int 区间[l,r]的最大值
 */
int f(const vector<int>& arr, int l, int r)
{
    // base case 基线条件：当左右边界相等，区间只有一个元素，直接返回该元素，递归终止
    if (l == r)
    {
        return arr[l];
    }

    // 计算中间位置，把当前区间切分成左右两部分
    int m = (l + r) / 2;

    // 递归求解左半区间 [l, m] 的最大值
    int lmax = f(arr, l, m);
    // 递归求解右半区间 [m+1, r] 的最大值
    int rmax = f(arr, m + 1, r);

    // 合并子问题结果：返回左右两部分的较大值
    return max(lmax, rmax);
}

/**
 * @brief 对外暴露的接口，用户只需要传入数组，不用关心边界
 * @param arr 输入数组
 * @return int 数组最大值；空数组返回0（业务可自行修改为抛异常）
 */
int maxValue(const vector<int>& arr)
{
    // 防御：空数组处理
    if (arr.empty())
    {
        return 0;
    }
    // 调用递归，处理整个数组区间 [0, size‑1]
    return f(arr, 0, (int)arr.size() - 1);
}

int main()
{
    vector<int> arr = {3, 8, 7, 6, 4, 5, 1, 2};
    // 调用接口获取最大值并打印
    cout << "数组最大值 : " << maxValue(arr) << endl;
    return 0;
}

```

运行输出：

```plain
数组最大值 : 8
```

## 二、递归到底是怎么执行的？
很多初学者觉得递归很"玄学"，函数自己调用自己，到底谁先谁后？其实只要抓住两个角度，递归就不再神秘。

### 2.1 从思想上理解：画递归调用图
对于新手来说，**画递归调用图是分析递归最重要的手段**。

以数组 `{3, 8, 7, 6, 4, 5, 1, 2}` 为例，整个递归过程是一棵二叉树：

![求数组最大值的递归调用图](/images/recursion-tree.png)

+ **向下的过程（递）**：不断把区间二分，直到 `l == r` 触达 base case，返回元素本身。
+ **向上的过程（归）**：每一层拿到左右子问题的结果后，做一次 `max` 比较，把结果返回给上一层。
+ 最终根节点 `f(0,7)` 拿到的就是整个数组的最大值。

> 💡 **一句话总结递归**：递归 = 拆解子问题 + base case 终止 + 子问题结果合并。
>

### 2.2 从实际上理解：递归底层是系统栈
递归不是玄学，它的底层就是**利用系统栈来实现的**。

每次调用一个函数，系统都会在栈上为这个函数分配一个栈帧（stack frame），保存函数的参数、局部变量、返回地址等信息。递归调用时，新的栈帧不断压入栈中；当函数返回时，栈帧弹出，回到上一层继续执行。

以上面的代码为例，执行 `f(arr, 0, 7)` 时：

1. 压入 `f(0,7)` 的栈帧，执行到 `lmax = f(arr, 0, 3)`，暂停，等待子调用返回。
2. 压入 `f(0,3)` 的栈帧，执行到 `lmax = f(arr, 0, 1)`，暂停。
3. 压入 `f(0,1)` 的栈帧，执行到 `lmax = f(arr, 0, 0)`，暂停。
4. 压入 `f(0,0)` 的栈帧，触达 base case，返回 `arr[0] = 3`，栈帧弹出。
5. 回到 `f(0,1)`，继续执行 `rmax = f(arr, 1, 1)`，返回 `8`，然后 `max(3,8)=8`，返回，弹出。
6. ……以此类推，所有栈帧依次弹出，最终回到 `f(0,7)`，得到结果。

所以递归的本质就是：**系统帮你维护了一个调用栈**。

## 三、递归一定能改成非递归吗？
### 3.1 结论：任何递归都可以改成非递归
**任何递归函数都一定可以改成非递归。**

原理很简单：递归用的是系统栈，那我不用系统栈，**自己手动压栈（用内存空间模拟栈）**，不就实现了同样的逻辑吗？这就是递归转非递归的核心思路。

### 3.2 递归改成非递归有必要吗？
答案是：**工程上几乎一定要改，算法笔试或比赛中能通过就不改。**

具体分两种场景：

+ **工程上**：递归深度不可控，数据量一大就可能栈溢出（StackOverflow）。所以除非你确定数据量再大递归也一定不深（比如归并排序、快速排序、线段树、很多平衡树等，递归深度是 `O(log n)` 级别，很安全），否则工程代码里通常要把递归改成非递归，或者显式控制递归深度。
+ **算法笔试/比赛中**：能通过就不改。递归代码写起来简洁、不容易出错，非递归代码又长又容易出 bug，比赛中优先保证正确性和编码速度。

> ⚠️ 注意：快速排序虽然平均递归深度是 `O(log n)`，但最坏情况下（数组已有序）会退化成 `O(n)`，可能栈溢出，所以工程上的快排通常会做优化（如三数取中、递归深度阈值切换到堆排序等）。

## 四、Master 公式（主定理）：一招算递归时间复杂度
写递归代码容易，但面试时面试官经常会追问："这个递归的时间复杂度是多少？" 这时候就需要 **Master 公式（主定理）** 登场了。

### 4.1 适用前提：子问题规模必须相同
⚠️ **Master 公式不是万能的，它只能解决「所有子问题规模相同」的递归。**

比如上面求最大值的例子，每次都把数组均匀二分，左右子问题规模都是 `n/2`，这就可以用 Master 公式。但如果递归拆出来的子问题规模不一样（比如一个是 `n/3`，另一个是 `2n/3`），就不能直接套 Master 公式，需要用递归树等方法分析。

### 4.2 公式形式
Master 公式的标准形式：

$T(n) = a \cdot T\left(\frac{n}{b}\right) + O(n^c)$

其中 `a`、`b`、`c` 都是常数，含义如下：

| 参数 | 含义 |
| --- | --- |
| `T(n)` | 处理规模为 `n` 的数据所需要的总时间 |
| `a` | 每次递归生成了多少个子问题（代码里写了几次递归调用），`a ≥ 1` |
| `b` | 每个子问题的规模是原问题的 `1/b`，`b > 1` |
| `O(n^c)` | **除去递归调用之外**，当前层做分解、合并等操作的时间复杂度，`c` 为常数 |


### 4.3 三种判定规则
算出 `log(b, a)`（即以 `b` 为底 `a` 的对数），然后和 `c` 比较：

1. **如果** `log(b, a) < c`：时间复杂度为 `O(n^c)`
2. **如果** `log(b, a) > c`：时间复杂度为 `O(n^log(b,a))`
3. **如果** `log(b, a) == c`：时间复杂度为 `O(n^c · log n)`

> 💡 **记忆口诀**：比较 `log(b,a)` 和 `c`，谁大听谁的；两者相等，多乘一个 `log n`。
>

### 4.4 用 Master 公式分析求最大值的递归
回到我们开头的例子，递归式为：

$T(n) = 2 \cdot T\left(\frac{n}{2}\right) + O(1)$

+ `a = 2`：每次拆成 2 个子问题（左半、右半各一次递归调用）
+ `b = 2`：每个子问题规模是原问题的 `1/2`
+ `c = 0`：除递归外，只做了求中点、`max` 比较，都是常数时间 `O(1) = O(n^0)`

计算：`log(2, 2) = 1`，而 `1 > 0`，满足第 2 种情况。

所以时间复杂度为：`O(n^1) = O(n)`。

这和我们的直觉一致——虽然用了递归二分，但每个元素都要被访问一次，整体还是线性时间。

### 4.5 常见算法的 Master 公式分析
| 算法 | 递归式 | a | b | c | log(b,a) vs c | 时间复杂度 |
| --- | --- | --- | --- | --- | --- | --- |
| 归并排序 | `T(n) = 2T(n/2) + O(n)` | 2 | 2 | 1 | `1 == 1` | `O(n log n)` |
| 二分查找 | `T(n) = 1·T(n/2) + O(1)` | 1 | 2 | 0 | `0 == 0` | `O(log n)` |
| 递归求最大值 | `T(n) = 2T(n/2) + O(1)` | 2 | 2 | 0 | `1 > 0` | `O(n)` |
| 二叉树遍历 | `T(n) = 2T(n/2) + O(1)` | 2 | 2 | 0 | `1 > 0` | `O(n)` |


### 4.6 一个补充：特殊形式的递归
有一种递归形式不在 Master 公式的三种标准情况里，但也很常见：

$T(n) = 2 \cdot T\left(\frac{n}{2}\right) + O(n \cdot \log n)$

它的时间复杂度是：

$O(n \cdot (\log n)^2)$

这个证明过程比较复杂，记住结论即可。它出现在一些需要在每一层都做 `O(n log n)` 操作的分治算法中。

## 五、避坑提醒
1. **子问题规模不同不能用 Master 公式**：比如递归拆成 `2n/3` 和 `n/3`，子问题大小不一样，不能套公式，需要用递归树分析法。
2. `a`、`b`、`c` **必须是常数**：不能是变量，否则不适用。
3. `O(n^c)` **是刨除递归调用本身的开销**：不要把递归调用的时间算进 `f(n)` 里，`O(n^c)` 只算当前函数中除了递归调用之外的操作。
4. **递归深度要警惕栈溢出**：工程代码中递归深度如果可能达到 `O(n)` 级别，一定要考虑改成非递归或增加深度保护。

---

## 六、总结
1. **递归的本质**：递归不是玄学，底层就是系统栈。从思想上画递归调用图，从实现上理解系统栈压栈弹栈，递归就不再神秘。
2. **递归两要素**：base case（终止条件）+ 拆解子问题并合并结果，缺一不可。
3. **递归转非递归**：任何递归都能改成非递归，核心是自己手动模拟栈；工程上尽量改，比赛中能过就不改。
4. **Master 公式**：仅限子问题规模均等的分治递归，套入 `T(n) = a·T(n/b) + O(n^c)`，比较 `log(b,a)` 和 `c`，三种情况直接读出时间复杂度。

> 🚀 **拓展思考**：如果递归拆出来的子问题规模不相等，Master 公式失效，这时就要学习**递归树分析法**——把每一层的开销加起来，同样能算出时间复杂度。后续文章可能会讲解。
